Two processes, one socket. The server owns no state beyond a health cache and a per-process token secret; everything durable lives in the daemon.

Request lifecycle

Every tool call runs the same six stages. Stages 1–3 can reject without touching the daemon.

  1. Schema validationserver.ts
    zod shape plus explicit byte, charset, and range checks. Failures return INVALID_INPUT before any I/O.
  2. Health and capability gatehealth-gate.ts
    ok === true, exact API version, required capability strictly true. Cached 1.5 s, single-flight.
  3. Authorizationallowlist.ts
    Write tools only. Canonicalize, then path-component containment. Input and kill authorize the daemon's own record.
  4. Transportdaemon-client.ts
    HTTP over the Unix socket with timeouts, 4 MiB caps, and abort propagation.
  5. Normalization or output pipelinenormalize.ts · read-output.ts
    JSON becomes stable camelCase; PTY event streams are sanitized and tokenized.
  6. Result shapingserver.ts
    One JSON text content item, or isError with a structured error body.

Security model

The daemon has no authentication — trust is same-user access to a local Unix socket. An unguarded bridge would therefore hand an LLM the ability to spawn PTY processes anywhere on the machine. Narrowing that authority is the point of the project, not a feature of it.

Controls

  • Deny by default. An unset or empty allowlist means every write tool is denied.
  • Fail-fast configuration. Any invalid allowlist entry aborts startup, naming the entry position but never its value.
  • Authoritative record. send_input and kill_session authorize the daemon's own project_root, never a caller-supplied path.
  • Component containment. Containment is path-component based after symlink resolution, so /work/app2 is never inside /work/app.
  • Fail closed. Missing paths, symlink escapes, dot-dot traversal, dead directories, and lookup failures all deny.
  • Excerpt redaction. Memory excerpts are blank by default; revealRequired or any non-public classification forces redaction even when enabled.
  • No sensitive logging. Prompts, input, output, excerpts, env values, tokens, and raw daemon bodies are never logged. Stdout is exclusively JSON-RPC.

What this explicitly does not guarantee

  • The allowlist is an authorization gate, not a process sandbox. A launched harness keeps full same-user OS authority.
  • Tool results are untrusted content with respect to prompt injection. Encoding is sanitized; meaning is not.
  • Resume tokens are integrity-protected but not encrypted, and carry un-emitted output state.
  • Anyone with same-user access can bypass coven-mcp by talking to the daemon directly.

Output pipeline

Daemon events carry raw PTY bytes: ANSI escapes, carriage-return rewrites, C0 and C1 controls, lines split across events, and payloads double-encoded as JSON strings. Three modules turn that into text an LLM can read, without ever losing position.

Sanitizer — sanitizer.ts

  • Terminal state machine with eight states: ground, escape, charset, csi, osc, oscEsc, str, strEsc.
  • Emits only on a newline reached in ground state, so an escape sequence split across events can never leak.
  • Carriage return overwrites from the line start, so progress bars collapse to their final visible state.
  • Pending state is compacted — the current line buffer plus any in-progress escape — never accumulated raw history. Without this, a long-running progress bar would grow state without bound.

Resume token — resume-token.ts

base64url(payload).base64url(HMAC-SHA-256(payload)), where payload is { v: 1, sessionId, afterSeq, pendingRawB64 }. The secret is a random 256-bit value per process; pending state is UTF-16LE so a chunk split inside a surrogate pair survives. Tokens die with the process by design — recover with afterSeq set to the last observed lastSeq.

Invariants

  • An event is consumed only once its emitted text and pending state both fit the budget — try before commit.
  • A terminal session completes only after one further drain returns empty, so racing trailing output is never dropped.
  • An error never discards text already produced in the same call.

Error taxonomy

Upstream contract

Pinned to OpenCoven/coven at 1fe9a744356ea3af6b47a3d497a483513b36eb15 (CLI 0.0.34). Six behaviors were verified against a live daemon rather than assumed from documentation — each is absorbed at a single boundary so it cannot leak into tool code.

BehaviorAbsorbed by
Requests are camelCase and session records reply snake_case — but the events envelope is camelCase while its event objects stay snake_case.normalize.ts
payload_json is a JSON string requiring a second parse.read-output.ts
A fifth, undocumented event kind kill exists alongside output, input, status, exit.read-output.ts
GET /sessions returns a bare array without pagination params and an envelope with them; GET /memory is always a bare array.normalize.ts
Health advertises string capabilities such as eventCursor: "sequence", so a truthiness check would wrongly grant permission.health-gate.ts
The daemon reports covenVersion: "0.0.0" even on a 0.0.34 install, so gating must use apiVersion and capabilities.health-gate.ts
